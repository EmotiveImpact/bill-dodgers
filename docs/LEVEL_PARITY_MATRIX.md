# Bill Dodgers: 42-level native parity matrix

Audit date: 2026-11-09. Scope: the executable sources in `game/` and the current Godot implementation in this checkout. This is a static implementation audit, not a playtest or a claim that all levels are complete.

## Conclusions and evidence rules

- The game has **42 levels, six world-specific runtime families, seven principal boss encounters including the 1-1 Jar Thief, and additional mini-bosses/set pieces**. Copying the 1-1 loop across the catalog cannot produce the whole game.
- **Current native coverage is twenty-one solo progression slices (all World 1, World 2 and World 3 stages), plus 21 layout previews.** All 42 META payloads and source art are imported, but import is not behavior. The other 21 levels do not currently run their enemy waves, objectives, rides or bosses. Shared movement, aiming, abilities, static collision and receipt collection are exposed in previews and are not proof of level parity.
- Read each level's executable hooks and META, not just `game/index.html` descriptions. Several menu descriptions refer to abandoned or shuffled designs. In particular: 2-3 is a stockroom climb, 2-4 a trolley dash, 2-5 a bakery; 3-4 is a big-top rigging climb and 3-5 a trailer ride; 4-2 is the old-town climb, 4-3 towel defence, 4-4 harbour chase and 4-5 boat ride.
- There is copied, **dormant** Jar Thief code in later worlds. A function's presence alone does not mean that boss is used. Dispatch sites and active level configuration decide coverage.
- Source references below are repository-relative. `META` is on a very long line in each HTML file; the readable identical data is in `godot/content/levels/<id>.json`. Asset URL conversion is the only intended META transformation. `godot/content/manifest.json` records original source SHA-256 values. Function names are stable anchors when line numbers move.
- JS timers use milliseconds and velocities usually pixels/ms; Godot uses seconds and pixels/s. Preserve units and call order deliberately. Do not silently change balance while translating.

## Native coverage definitions

| Code | Meaning |
|---|---|
| **S** | Solo progression slice implemented and regression-tested; full fidelity, human difficulty and device QA still pending. |
| **I** | Native runtime integrated; expanded full-character acceptance is still in progress. |
| **D** | Data/assets imported; layout preview only. Its complete mechanics and clear condition are not integrated; some reusable components may exist (P). |
| **P** | A reusable piece exists, but is not integrated or proven for this level/world. |

The shared `godot/src/native_levels.gd` registry now routes all 42 stages to separate World 1–6 runtime/combat/painter families. Worlds 1–5 have complete six-housemate assisted route evidence; World 6 expanded acceptance is in progress. Registry support means native integration, not a signed phone build or complete fidelity/difficulty certification. All six movement-card runtimes are integrated. See each world's current implementation and acceptance notes, plus `NATIVE_PORT_PLAN.md` for the last frozen aggregate checkpoint.

## Reusable mechanics with parameters that must survive extraction

- **Camera domains:** ordinary encounter locks, always-forward auto scrolling, fixed-width bus/lorry arenas, vertical player-follow, sofa tether, boat/cradle deck-relative movement, and scripted scene jumps are separate modes. Mark per-frame ordering: carry surfaces, player movement, objective update, enemy update, camera update and rendering cannot be arbitrarily reordered.
- **Gate/puzzle state:** W2 pressure plates hold open 5.2s solo/CPU versus 2.6s with two humans; shoot buttons hold 6.5s. Gates must not close onto occupied players. W6 scene doors wait for preceding waves, mini-boss clearance and no nearby bots. A static collider cannot substitute for either.
- **Moving surfaces:** W3 trapezes have x/y motion and carry their riders; W4 bobbing boats and W5 lifts/vehicle slots change surface positions; W6 belt velocity is a raw fourth column. Retain last-frame displacement, current top, one-way flag and enabled state; transport players, appropriate bots, coins and items according to source, not a universal rule.
- **Conditional movement:** mud/wellies, W2 ice/flour, W3 tied legs, checkout bags/crates, sofa carriage, W4 swimming/fall recovery and W6 debit attachments each alter specific control paths. Temporary states must clear on death/restart/scene changes as their source does.
- **Warnings before harm:** falling-box shadows; low bridge/branch warnings; bakery flame phases; scanner height tells; lift-drop warnings; fee/rock rain targets. Visuals convey actionable timing and belong in the gameplay contract, not final cosmetic polish.
- **Set-piece ownership:** W4 avalanche and melon controllers wait for spawned hazards to finish; W5 van/flatbed surfaces wait for passengers before departing; W6 hold enemies attack the lift-door goal. Enemy counts alone cannot decide every wave/scene completion.
- **Timed objectives are not one class with one outcome:** 3-S time/all-coins ends collection; 4-3 timeout is successful defence; 4-S timeout completes with zero time bonus; 5-5 elapsed ride time still needs waves; 5-S timeout still needs waves; 6-2 elapsed time can be reduced by attackers; 6-S timeout directly starts its clear flow. 2-S's configured timer is dormant.

## Source discrepancies and explicit decisions to retain

These are findings, not permission to redesign the source. If a port fixes one, record the deviation and add a test instead of calling it exact parity.

1. **2-S timer:** `level.timer=100000` and start text imply 100s, but runtime never reads `LV.timer`. Actual executable completion is distance plus waves. Decide source-faithful behavior or an intentional repaired timer before implementation.
2. **1-3 final hazard batch:** `levelUpdate()` schedules `between` obstacles after fights, but the generic end test can finish as soon as the last wave is done. The native objective preserves that source wave gate without adding an all-obstacles requirement; all-six automated route runs nevertheless cross all twenty-five obstacles. Browser/human comparison remains pending.
3. **3-2 and 3-5 auto-stage clear:** festival `endOK()` accepts auto stages without the normal all-waves predicate. Harvester defeat is therefore not an explicit completion prerequisite. Do not silently add a gate.
4. **5-S clock:** `W5.atEnd()` becomes true at zero time, but `updatePlay()` still demands `waves.every(done)`. A player waiting near the start does not immediately clear on expiry. A deliberate timeout redesign should not be hidden inside a generic timer helper.
5. **6-S completion:** finishing x≥15,740 awards `ceil(seconds left)` to kitty and lead player and bypasses waves; timeout sets `endT` directly without that bonus. Do not carry W5 wave gating into it.
6. **Old menu descriptions:** no implemented kettle/flat-kitchen chase in 1-S; no giant-fridge dessert drop in 2-S; no shoot-the-cans objective in 3-S; no scoop-stacking game in 4-S; no rhythm game in 5-S; no coffee cargo inventory in 6-S. Menu copy is not sufficient implementation evidence.
7. **Dormant copied code and late patches:** later HTML pages include old boss routines and generic classes that active world hooks bypass. Every page also has injected character-special, input and aiming wrappers near its end. Port the executed function chain, not the first same-named function you encounter.
8. **Data geometry is not necessarily camera extent:** 5-3 and 6-4 are 738px wide yet thousands of pixels tall; 1-3/5-5 fixed-width rides progress by waves/time. 6-5's narrative is window cleaning up a building, but its implementation is horizontal scrolling.
