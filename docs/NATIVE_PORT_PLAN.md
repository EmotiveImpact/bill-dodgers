# Native port decision and delivery plan

## Decision

Use **Godot 4** for one native 2D game codebase exported to iPhone and Android.
The user explicitly requested a proper game engine and the whole game, and instructed us to leave the repository public for now. No repository visibility change is part of this implementation.

The source game is a custom Canvas 2D engine embedded in 42 HTML files, with six worlds, painted backgrounds, sprite-sheet animation, multitouch controls, enemies, bosses, abilities, co-op and story scenes. It is not a React application.

- React Native/Expo is appropriate for Commune's app shell, account screens and menus. It does not automatically run Canvas gameplay as native React Native drawing. A WebView would preserve the JavaScript engine, not port it.
- Capacitor/WebView could provide a quick offline version of the current game. It was not selected as the final architecture because the user requested a game-engine port.
- Godot is well suited to this 2D game, offers one codebase, native input/lifecycle/rendering and iOS/Android exports. It avoids rewriting the game separately in Swift and Kotlin. Its MIT engine licence does not grant rights to the game's art/fonts/audio.
- Unity could also work, but this game does not currently need its heavier ecosystem or 3D feature set. Neither engine magically imports the JavaScript mechanics.

## Content preservation

The importer retains exact META data for every original level, all embedded images from every HTML/JavaScript file, shared sprites, story images, bundled fonts, title art and a verbatim cutscene JavaScript reference. SHA-256 records identify source files and output assets. Assets are deduplicated, not recompressed or visually edited. JavaScript behavior outside META remains in the original `game/` source, identified by hashes.

All 42 stages now route to dedicated native solo runtime/combat/renderer families. This is integration coverage, not a finished-phone-game claim. World 4 and World 5 each have all 42 housemate/stage assisted route passes; expanded collectibles and World 6 acceptance are in progress. The original painted art is retained at source resolution, without pixel-grid or colour-reduction effects.

## Verified build prerequisites

The validation workspace has Godot 4.6.3, but no Android SDK, matching export templates or full JDK. No connected macOS build machine was available to inspect Xcode/signing. Android needs those official toolchain prerequisites; iOS needs macOS/Xcode and the chosen Apple team configuration. No installation, account creation or signing changes have been made. Check the user's existing setup before assuming new accounts or payments are needed.

## Commune access and release caveats

Existing web README says Worlds 1–2 are free and 3–6 member-only, with source expected private; GitHub was actually public when inspected. The user has since explicitly chosen to leave it public. This patch neither changes visibility nor changes the web deployment's free/member filtering.

Commune's current `apps/native` is Expo 54 / React Native 0.81.4, but its README says hosted sign-in is not connected. Current architecture also says billing/entitlements are not implemented. Do not mistake the older mobile-v2 RevenueCat dependency, a login, household membership or a local boolean for a verified paid entitlement. A future full-game distribution decision should be explicit rather than silently imposing the old member-only web rule or inventing a new checkout.

The web membership CTA points at an external pricing page. Do not automatically carry it into a store build. Verify current Apple/Google requirements for the chosen digital-content access model and storefronts before implementation.

No public push, deployment, repository-visibility change, paid service, account creation, legal agreement, signing credential or store submission was performed for this implementation.
