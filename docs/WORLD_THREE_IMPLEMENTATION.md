## 1. Coordinates, schemas and current host boundary

Source time is **milliseconds**, speed **px/ms**, acceleration **px/ms²**; native time is seconds, speed px/s and acceleration px/s². Multiply source speeds by1,000 and accelerations by1,000,000, divide clocks by1,000. Source `p.y` is feet relative to `GROUND=482`; native `host.player.y` is **absolute feet**. `VW=960`, `VH=540`, `ZOOM=1.3`, `WV=round(960/1.3)=738`, `viewTop=camY+540-540/1.3`. Source clamps frame dt to34ms. Fall lines are stage-specific, not universally742 or882.

Lossless schemas:

- Solids/platforms: `[x0,x1,absoluteTop,properties?]`; properties in W3 are `style`, `nospawn`, `nodrop`, `conv`, `base`. Construct solids followed by platforms with stable identities; `NS=solids.length` and mover/trailer/stage indexes reference **platform index**, not combined index. Solids extend downward indefinitely; platforms are one-way.
- `l3.waves`: `[cameraAt, [[delayMs, side, kind, pairOnly?], ...]]`. `side=t` means tent, `k` delivery-drone-carried robot, `d` flying drone. They are not enemy type strings or left/right aliases. Normal type tokens are `rush`, `throw`, `flat`.
- `coinRows`: `[x0,y,spacing,count,arcHeight]`, unlike W2's `[coins,x0,x1,y,count,arc]`; every row spawns all its coins at once in the first late update. Coin i is `(x0+i*spacing, y-sin(i/max(1,count-1)*PI)*arcHeight)`.
- `tents`: `[x,feet,col?,kind?]`; default col0, kind`dome`; cutout names begin `cut:`. `mud`: `[x0,x1]`; `fires`: `[x,feet]`; `duck`: `[x0,x1,undersideY,kind?]`; `gaps` records holes already present in solid geometry, not a second collision plane.
- `movers`: `[platformIndex,amplitudeX,amplitudeY,periodMs,phaseRadians?]`; `spots`: `[x,y]`; `receipts`: `[x,y]` are **pickup/draw centers**, not ground feet; `skill`: `[x,y,"ground-pound"]`.
- `l3.scenes`: `{x,to?,key,landF?,skyF?,drift?,wipe?,label?,feet?}`. `l3.check` is one scalar trigger and `checkY` is **flag presentation only**. `events`: `[cameraAt,title,subtitle]`. `l3.mini`/`boss`: `{kind,name,hp,hp2,cam?,sub,mini?}`; `mini` truthiness selects miniboss lifecycle. `l3.harv={cam,hp}`, `trailer={plat}`; `stage` numeric selects Tout platform. Zero is a valid stage index; false is not.

Recommended runtime API, aligning current host geometry and phase seams:

- `reset(host,seed)`, `invalidate_run()`, `surfaces(host,skip_platforms=false)`, `below(host,x,y)`, `land_on(host,x,y0,y1,skip=false)`, `wall_clamp(host,x0,x1,feet)`, `inside_wall(host,point)`, `recover_from_fall(host)`, `after_motion(host)`.
- Surface result `{row,plat,id,properties,dx,dy}` (or equivalent fields) keeps one stable object per live surface. Rows are private copies; never mutate imported JSON. All collision, spawn, ability, skill and painter paths consume the same current rows.
- `base_displacement(dt,host,move)`, `carry_player(dt,host)` **before clamp**, `can_jump(host)`, `jump_multiplier(host)`, `allow_drop(host)` (respect current `nodrop`), `auto_displacement(dt,host)`, `after_camera(dt,host)` to capture this frame's actual camDX.
- `objective_tick(dt,host) -> ending|clear|empty` runs immediately after waves, before enemies. `after_pickups(dt,host)` performs the exact late rules below and may start a boss or clear the bonus. `finish_frame(host)` owns guarded wipe callbacks. Snapshot access must include current scene, elapsed, surfaces, tents, checkpoint, spots/movers/trailer, ties, harvester, darkness/fireworks and wipe state.
- Combat keeps W2-style `reset(host,participants,seed)`, `waves_tick`, `enemies_tick`, `projectiles_tick`, `pickups_tick`, `spawn(host,side,kind)`, `damage_enemy/kill_enemy/hit_crate`; add `start_boss(host,cfg)`, late `boss_tick`/`jar_tick`. Host `boss.state` must expose source-shaped `x,fy,hp,max,state,dizzy` for abilities without pretending this is the W1 Jar Thief. Runtime starts mini/main bosses at its late trigger point; combat alone advances them.
- Keep enemy `p` (absolute feet), `kind/type`, `state`, `hp`, `face`, `t`, `cd`, `flash`, `gone`, `entered`, `segment` **plus stable surface**, `fly/ride/carry/rise/dz/age/hitAge/hop`, and bubble fields. A bare `segment` array loses mover delta/properties. Player shots use existing `{p,v,enemy=false,damage,ghost,ghost_age}` adapters; bills preserve `flat,tie,big,g`. `big` changes art, not the W3 projectile hit radius.
- Renderer: `draw_sky`, `draw_level`, `draw_mid`, `draw_enemy`, `draw_boss`, `draw_jar`, `draw_player_back/front`, `draw_front`, `draw_hud`, with pure command builders. Receipt/skill artwork belongs in the source level layer, not blindly in W2's mid layer. The host must not draw them twice.

Current host facts to account for, not hypothetical work: `NativeLevels` centralizes supported families and source-ability-shot mode; `main.gd` currently selects W1/W2 runtime/combat, routes wall tests only to W2, applies W2 receipt offsets/rewards, and only gates its34ms clamp on W2. The current W3 `movement_skills.collect_card` geometry is already correct, but preview availability does not mean the course is implemented. `_source_ability_shots` must include supported W3 stages so skill/ability hits are ghost shots, bubble reinsertion is ordered and all-down is deferred. W3 character speed bonuses also need `spdMul`; W2's deliberately unscaled bonus nudge is wrong here. `_complete_level`/story dispatch reads W1/W2 text names, whereas W3 uses `meta.l3.txt`. Extend family dispatch coherently, not by making W3 accidentally satisfy `_native_world_two()`.

## 2. Exact frame order

Sources: base `updatePlayer`407–447, `updatePlay`631–674, `updateBots`480–523, `updateShots`528–558, `updateCoins`559–580, festival `levelUpdate`1294–1328, ability wrappers1990–2035, final input/aim wrappers2217–2249.

### Geometry, movement and moving-surface rules

`landOn` picks highest crossed top in `[oldFeet−1,newFeet+.5]` with inclusive x endpoints; `below` top≥queryY−2. WallClamp ignores platforms and tops≥feet−6, holds14px from the crossed side; insideWall is strict x and y>top+4. These same live queries apply to shots and ability balls. Landing records surface identity; standing support tests feet±2. Safe position updates only on non-platform solids at least90px inside either end.

- Normal jump−.98, gravity`.0033`, terminal1.5; platform Down+freshJump gives vy`.12`/drop260ms unless `surf.nodrop`. Tied blocks **ordinary jump only**, not this drop path or independently unlocked shared air skills. Normal/split fire intervals210/260ms; projectile speed`.78`. Damage: one heart, inv1500ms, lock420ms, knockback±.35; damp to0 when |vx|<.01. The existing ability damage guards remain active.
- Mud requires grounded, strict zone x and |feet−482|<4. Without wellies base movement×.55 and ordinary jump×.84; tied adds×.45 to movement, so combined=.2475. No mud penalty on upper bale/van roofs or airborne movement. Ability bonus nudge also multiplies by `spdMul` (line1878); Ama jump×1.09 and Mei special jump×1.06 run after base physics, and Leo held-jump fall cap remains `.34`.
- `carry`1175 checks grounded then cached surface; if invalid/outside x or |surface.top−(dy||0)−feet|>4, reacquire with landOn(feet±4). Apply `conv*dt`, then dx, then dy. `conv` affects players only. No universal crate/item/coin or enemy conveyor transport. Movers' dx/dy are **displacements**, not speeds.
- Late mover formula: k=sin(levelT/period*6.283+phase), x=baseX+ampX*k, top=baseTop+ampY*abs(k); dx/dy=current−previous. Trailer adds this frame's camDX to both ends and sets dx=camDX. Late bots with a segment whose dx is truthy, no hop and state≠pop receive that dx and snap fy=segment.top; this also sees bubbled bots after reinsertion. A pure vertical dy without dx would not carry bots in this source.
- AutoRun requires play, no `BD.wiping`, levelT>1800, no living boss, and no endT. Auto clamp can put a player inside a solid; `squash` tests insideWall(player.x,feet−10), then normal fall recovery/hurt. It does not instantly kill or spawn an extra gap hazard.
